# Handoff: Surlap — 고등학생용 통합 캘린더 앱 (Android)

## Overview
Surlap은 학교 시간표(NEIS)·급식·학사일정·개인 일정·할 일·기록(하루/기간)·공유 캘린더·스포츠 일정·생일을 하나의 캘린더로 모으는 모바일 앱입니다. 이 핸드오프는 앱 전체 30개 화면의 **고해상도 디자인 목업**과 각 화면의 동작 규칙·상태·엣지케이스를 담고 있습니다.

원본 코드베이스: `github.com/kev208dev/Surlap` (Flutter / Dart, branch `main`).

## About the Design Files
이 번들에 들어있는 파일은 **HTML로 만든 디자인 참조 자료**입니다. 의도한 모양과 동작을 보여주는 프로토타입이며, 그대로 복사해서 쓰는 프로덕션 코드가 아닙니다.

작업 내용은 이 HTML 디자인을 **대상 코드베이스(Flutter)의 기존 환경과 패턴으로 다시 구현**하는 것입니다. 기존 위젯 구조, 테마 시스템(`lib/core/theme/app_theme.dart`), 상태 관리 방식을 그대로 쓰고, 아래 문서의 값(색상·타이포·간격·동작 규칙)을 Flutter 테마 토큰으로 옮겨 적용하세요. HTML/CSS를 WebView로 감싸는 방식은 의도가 아닙니다.

## Fidelity
**High-fidelity (hifi)** — 최종 색상, 타이포그래피, 간격, 인터랙션이 모두 확정된 픽셀 단위 목업입니다. 개발자는 Flutter의 기존 위젯과 패턴으로 이 UI를 픽셀 단위로 재현해야 합니다.

목업 캔버스는 **412 × 896 dp** (Android 기준, 모서리 반경 33px 프레임 안에 렌더). 상단 상태바 34px, 하단 탭바 포함.

## Screens / Views

총 30개 화면, 9개 그룹. 각 화면의 코드는 `Surlap.dc.html` 안에 `v_<screenId>` 플래그로 조건 렌더링되어 있고, 화면별 규칙은 같은 파일의 `NOTES` 상수에 그대로 들어있습니다(우측 패널에 표시되는 스펙 노트).

### A. 첫 실행

**A1 · `splash` — 스플래시 · 세션 확인** (spec §1)
저장된 세션과 자동 로그인 상태를 확인하는 동안 **최소 3.1초** 유지. 초기화 순서: 로컬 저장소 → 알림·시간대 → Supabase(설정값이 있을 때만).
- Supabase 설정이 없으면 초기화를 건너뛰고 앱은 그대로 사용 가능.
- 최초 실행이면 언어 선택으로, 이미 완료했으면 홈으로.
- 온보딩 완료 여부는 기기 설정으로 저장되어 반복되지 않음.
- 상태: 로딩(기본) / 세션 있음 → 홈 / 세션 없음 → 첫 실행 흐름.

**A2 · `lang` — 언어 선택** (spec §1)
한국어·영어·일본어·중국어·스페인어 5개. **계정이 아니라 기기에 저장**.
- 언어·온보딩 완료·캘린더 이동 설정·알림 설정은 계정 범위 밖 → 클라우드 동기화와 로컬 JSON 백업에 포함되지 않음.
- ⚠ 현재 목업의 실제 번역은 한국어만 완성. 나머지 4개 언어는 UI 자리만 존재.

**A3 · `onboard` — 온보딩** (spec §1)
기능 소개 3장. 건너뛰기 가능, 완료 여부 저장.
- 설정에서 사용 설명서를 다시 열 수 있음.
- 카테고리 관리·길게 누르기 안내는 1회성 코치마크로 별도 제공(홈 진입 시 1회).

**A4 · `utype` — 사용자 유형** (spec §1)
일반·초등·중등·고등·대학. **초·중·고만 NEIS 학교 연동**.
- 학년: 초등 1–6, 중·고 1–3. 학교를 먼저 고르면 학교 종류에서 사용자 유형을 유추.

**A5 · `auth` — 로그인 · 계정 만들기 · 게스트** (spec §2)
계정 없이도 전부 로컬 사용 가능. 아이디는 **영문·숫자·밑줄 4–20자**, 소문자 변환 후 `<id>@cal-id.local` 로 내부 변환.
- 지원: 아이디/비밀번호, Google OAuth, Apple OAuth(iOS·macOS 한정 — Android에서는 버튼 숨김), 게스트 모드, 자동 로그인 저장, 로그아웃.
- OAuth 콜백: `surlap://login-callback`, 외부 브라우저로 열림.
- ⚠ **화면에 그대로 고지해야 하는 항목**: 저장된 비밀번호는 Base64로 가릴 뿐 암호화가 아님. 게스트 데이터는 `guest::`, 계정 데이터는 `user_<uid>::` 접두사로 분리되고, 가입·로그인해도 게스트 데이터는 자동 병합되지 않음.
- 검증 실패 시 토스트: "아이디 형식을 확인해 주세요."

### B. 홈

**B1 · `home` — 오늘** (spec §5)
오늘 하루 요약: 다가오는 시간 일정, 오늘·날짜 없는 할 일, 급식, 오늘 내 일정 수, 다가오는 생일 4건, 가장 가까운 학사일정 카운트다운, 이번 주 스트립.
- **정렬**: 시간 일정 = 내 일정 + 반복 생성분을 시작 시각순 / 할 일 = 미완료 → 완료, 그다음 우선순위, 생성 시각순 / 생일 = 다음 생일이 가까운 순 최대 4건.
- **급식 상태**: 학교 미설정 · 불러오는 중 · 급식 없음 · 네트워크 실패(다시 시도). 직접 못 받으면 저장된 급식으로 대체.
- 내 일정은 편집기로, 생성·읽기 전용 항목은 상세 보기로 열림.
- **학사일정 강조**: 제목에 시험·방학·개학·졸업·입학·수능·체육대회·축제가 들어간, 지나지 않은 항목 중 가장 가까운 것.
- 지난 시각의 일정은 opacity 0.45로 감쇠.

**B2 · `widget` — 홈 화면 위젯** (spec §18)
홈 화면 위젯에 넘기는 데이터: 종일 6건, 시간 일정 8건, 오늘 할 일 6건, 완료 수, 전체 건수, 다음 시간 일정 위치, 오늘의 수동 시간표와 현재 교시·진행률·남은 시간·다음 교시.
- **갱신 시점**: 첫 프레임 이후 한 번 / 일정·할 일·카테고리·생일·필터·수동 시간표 변경 시 / 앱으로 돌아올 때 / 앱이 살아 있는 동안 1분마다. 동기화 오류가 앱 동작을 막지 않음.
- ⚠ 한계(화면 내 고지): 반복 생성 일정은 일반 일정으로 넣지 않음 / 시간표는 1–7교시 수동 데이터만 읽고 **한 교시를 50분으로 가정**(NEIS·템플릿 우선순위 엔진 미사용) / 필터는 공유·스포츠·생일·학사에만 적용되고 내 일정에는 일관 적용되지 않음.

### C. 캘린더

**C1 · `year` — 연 보기** (spec §4)
12개월 전체를 한 화면. 월 탭 → 월 보기. 이전·다음 해 이동, 오늘로 이동. 항목이 있는 날짜에 점 표시.

**C2 · `month` — 월 보기 (고정 6주)** (spec §4 · §6)
**항상 6주 범위.** 주 시작 요일(월·일·토) 설정을 따르고 앞뒤 달 날짜로 범위를 채움. 같은 제목이 연속된 날짜에 걸치면 ID나 출처가 달라도 하나의 여러 날 막대로 묶고, 겹치면 레인으로 나눔.
- **상호작용**: 한 번 누르면 그 주의 내용을 먼저 펼침 → 같은 날짜를 다시 누르면 하루 보기로 이동. 항목이 없는 날짜는 바로 이동. **길게 누르면 날짜 작업 시트**, **두 번 누르면 동그라미 표시 토글**.
- **필터**: 월 보기는 내 일정에 카테고리 숨김을 적용. 여러 카테고리 중 하나라도 숨기면 그 일정이 숨겨짐. 카테고리 없는 일정은 `__none__` 필터를 숨겨야 사라짐.
- ⚠ 한계: 3일 플래너·하루 보기는 내 일정에 카테고리 필터를 일관 적용하지 않음(카테고리 화면에 고지) / "지난 기록 보기"를 꺼도 기록은 실제로 제거되지 않음.
- 오늘 칩: `sig` 배경 + `sig-ink` 글자. 선택 날짜: 1.5px `accent` 링. 항목 있는 날: `accent` 점.

**C3 · `planner` — 3일 플래너** (spec §4)
선택 날짜 기준 연속 3일. 24시간 시간 일정 + 종일 항목, 겹치는 일정은 충돌 레인으로 분할.
- 이전·다음은 3일씩 이동, 오늘로 복귀. **종료 시각이 없는 일정은 배치할 때 30분으로 계산.** 시간표 레이어 on/off. 내 일정은 편집기, 생성·외부 일정은 읽기 전용 상세로.

**C4 · `day` — 하루 보기** (spec §4)
종일·시간 일정, 날짜 있는 할 일, 공휴일, 학사일정, 생일, 공유 캘린더, 스포츠, 반복 생성분 전부 표시. 좌우 스와이프로 전날·다음 날.
- **편집**: 내 시간 일정은 위아래 드래그 이동, **15분 단위 스냅**. 아래 모서리 드래그로 종료 시각 변경, **최소 15분**. 학사·생일·스포츠 등 생성 항목은 이동·크기 변경 불가 — **점선 테두리**로 구분.

**C5 · `search` — 검색** (spec §9)
직접 저장한 일정과 할 일만, 대소문자 구분 없이 부분 일치. **날짜 내림차순.**
- **제외**: 시간표 일정 / 반복 생성 가상 일정 / 구독한 공유 캘린더 일정 / 스포츠·생일·공휴일·학사일정.
- **선택**: 날짜가 있는 결과는 그 날짜로 이동. 날짜 없는 할 일은 이동 없이 검색만 닫힘(토스트로 안내).
- 상태: idle(검색어 없음) / 결과 없음 / 결과 목록.

**C6 · `cats` — 캘린더 카테고리** (spec §10)
내 카테고리 생성·이름 변경·확인 후 삭제. 일정에 여러 카테고리 부착 가능.
- **구분 3종**: 내 카테고리 / 내가 공유 중(소유) / 구독 중(읽기 전용). 공유는 로그인 + Supabase 연결 모두 필요.
- 생성된 항목(생일·학사·공휴일·스포츠)은 해당 필터 ID로 숨김.
- ⚠ 한계: 숨김은 월 보기 기준 — 플래너·하루 보기·위젯은 내 일정에 일관 적용되지 않음 / 소유한 로컬 카테고리를 지워도 서버의 공유 행은 함께 삭제되지 않음.
- 기본 카테고리 예시 색: 학교 `accent`, 학원 `accent-2`, 개인 `neutral-500`.

### D. 일정

**D1 · `eventNew` — 일정 추가 · 자연어** (spec §7)
제목 **필수**, 날짜 **필수**, 시작·종료 시각 선택. 카테고리 0개·1개·여러 개.
- **자연어 인식(날짜)**: 오늘·내일·모레·3일 뒤·요일·이번주/다음주+요일·M월 D일·M/D. 요일만 쓰면 다음 그 요일, **오늘이 그 요일이면 다음 주**. 지난 월·일은 다음 해로 넘어감.
- **자연어 인식(시각)**: `9-10` · `9시~10시30분` · `9:00-10:30` · `3시` · `오후 3시` · `3시 반` · `15:30`. 인식한 토큰은 **제목에서 지우고** 24시간 `HH:mm`으로 정규화.
- **적용 규칙**: 제안은 적용하거나 무시 가능. 저장할 때는 **사용자가 직접 바꾸지 않은 칸에만** 자동 반영. 시작 시각을 지우면 종료 시각도 함께 지워짐.
- **충돌 검사**: 같은 날 **내 시간 일정과만** 비교, 최대 4건. 종료 시각 없는 기존 일정은 **60분**으로 계산. 생성·공유·스포츠·시간표 항목은 제외. 충돌 시 확인 단계 → "충돌을 무시하고 저장" 가능.
- **반복**: 매주·매월·매년, 간격 1로 저장, 종료일만 선택. 가상 일정을 편집하면 원본으로 이동 — **회차별 예외 없음**.
- ⚠ 한계: 현재 편집기는 새로 고른 날짜로 색인해서, 기존 일정의 날짜를 바꾸면 원래 날짜에서 지워지거나 새 날짜로 옮겨지는 것이 보장되지 않음 / 종료 시각이 시작보다 빨라도 막지 않고 충돌 경고만 건너뜀.
- 검증 토스트: "제목을 입력해 주세요." 저장 성공 토스트: "저장됨 · <날짜>".

**D2 · `eventRO` — 읽기 전용 상세** (spec §6 · §11)
생일·학사일정·공휴일·구독 캘린더·스포츠 일정은 편집 불가. **어디서 왔는지와 어떻게 없앨 수 있는지**를 보여줌.
- 규칙: 이동·크기 변경 불가 / 검색 대상 아님 / iCalendar 내보내기 제외 / 스포츠 모델에 중계 주소 칸이 있지만 실제로 채우지 않음 — **중계 실행 기능 없음**.

### E. 할 일

**E1 · `todos` — 할 일** (spec §8)
일정과 **별개 저장**. 제목 필수, 우선순위 없음·1·2·3, 날짜 선택.
- **상태 3단 순환**: 시작 전 → 진행 중 → 완료 → 시작 전.
- **정렬**: P1 → P2 → P3 → 없음 → 생성 시각.
- ⚠ 범위: 할 일은 계정별로 나뉘어 **로컬에만** 저장. 클라우드 사용자 데이터 동기화에 포함되지 않고, 로컬 JSON 백업에도 포함되지 않음.
- 헤더에 완료/전체 카운트 표시.

**E2 · `todoNew` — 할 일 추가 · 음성** (spec §8)
제목에서 날짜와 우선순위를 함께 읽음. **직접 고른 값이 인식값보다 우선.**
- **인식**: 오늘·내일·모레·3일 뒤·요일·이번주/다음주+요일·M월 D일·M/D / `p1`·`p2`·`p3`·"우선순위 N" / **중요·긴급은 P1**. 날짜를 명시적으로 비우면 날짜 없는 할 일.
- **음성 입력**: 한국어(`ko_KR`) 인식, 부분 결과 표시. **최대 60초, 무음 10초면 종료.** 마이크·음성 인식 권한 요청 및 오류 안내. 새 음성 결과를 적용하면 직접 고른 날짜·우선순위를 초기화해 다시 인식. **다국어 음성 모델 미제공.**
- 음성 UI 4상태: 대기 / 권한 요청 / 듣는 중(파형 애니메이션 `mic`) / 오류.

### F. 학교 · NEIS

**F1 · `school` — 학교 연결** (spec §12)
NEIS `schoolInfo`로 학교 검색, **최대 10곳** 표시. 학년·반을 고르면 학교명·학교 코드·교육청 코드·학교 종류·학년·반 저장.
- 이후: 시간표와 학사일정을 새로 받아옴. 사용자 유형 미선택 시 학교 종류에서 유추. 초등 1–6, 중·고 1–3.
- 상태: 검색 중 / 결과 없음 / 네트워크 실패(다시 시도). 필수 학교 식별자가 없거나 지원하지 않는 학교 종류면 시간표를 돌려주지 않음.
- 2단계 스텝 UI(학교 검색 → 학년·반).

**F2 · `timetable` — 시간표** (spec §13)
월–일 주간 시간표. **채우기 우선순위**: 교시 칸 = NEIS → 저장된 템플릿 → 수동 입력 / 점심 = 수동 → NEIS / 나머지 시간 = 수동 → 템플릿.
- **배치**: 1–4교시는 9·10·11·12시, 점심은 13시, 5교시부터 14시에서 한 시간씩. 세로로 붙어 있고 과목명이 같으면 한 과목으로 이어 표시.
- 수동 입력은 **요일·시각으로 색인되고 매주 반복**. 수동 입력은 플래너·하루 보기에서 시간표 레이어를 켰을 때만 보이고 **월 보기에는 들어가지 않음**.
- ⚠ 내부: 템플릿 블록·허용 요일·기간·날짜별 숨김·날짜별 추가 블록 엔진이 계산에는 쓰이지만 **완성된 편집 화면은 없음**.
- NEIS 출처와 수동 입력은 색으로 구분. 셀 탭 → 수동 입력 바텀시트("직접 입력 · 매주 반복").

**F3 · `ttExport` — 시간표 이미지** (spec §13)
시간표를 이미지로 만들어 갤러리 저장 또는 OS 공유 시트로 전송.
- 옵션: 주말 포함 여부 / 전체 시간 또는 학교 시간과 점심만. 갤러리 저장에는 사진 추가 권한 필요.
- 참고: 화면 캡처 유틸리티가 따로 있지만 현재 연결된 호출부 없음 — 실제 쓰이는 이미지 흐름은 시간표 내보내기.

### G. 기록

**G1 · `dayTpl` — 하루 템플릿** (spec §14)
매일 같은 항목을 채우는 템플릿. 적용 범위: 매일 / 선택한 요일 / 기간 / 명시 날짜. **명시 날짜는 다른 범위와 상관없이 항상 적용.**
- 프리셋 6종: 시험 공부 · 간단 일기 · 공부와 회고 · 습관 트래킹 · 건강 루틴 · 수업 기록.
- 저장: 값은 날짜 → 템플릿 → 항목 순으로 저장되고 입력 즉시 기록.
- ⚠ 항목 값을 지워도 비어 있는 상위 묶음이 반드시 정리되지 않음 / 템플릿을 지워도 지난 값 기록은 지워지지 않음.

**G2 · `dayTplEdit` — 템플릿 편집** (spec §14)
항목 추가·삭제·순서 변경, 적용 범위 지정. **항목 종류 11가지**: 숫자 · 한 줄 · 메모 · 체크 목록 · 별점 · 태그 · 진행 · 카운터 · 기분 · 슬라이더 · 시간 범위.
- **항목 규칙**: 별점은 1~설정 최대값, 같은 값 재탭 시 0 / 기분은 3단계 또는 5단계, 같은 값 재탭 시 해제 / 카운터 기본 단계 1, 음수 허용 / 진행 기본 목표 100 / 슬라이더는 **손을 뗄 때** 저장 / 시간 범위는 자정을 넘기면 다음 날로 계산.
- ⚠ 한계: 기간·명시 날짜 범위로 바꿀 수는 있지만 날짜를 고르는 컨트롤이 없음 — 명시 날짜는 달력의 날짜 작업으로 추가.

**G3 · `dayEntry` — 오늘 기록** (spec §14)
해당 날짜에 적용되는 템플릿의 항목을 바로 채움. **모든 입력은 즉시 저장.**
- ⚠ 표시: 고정 월 보기는 하루 템플릿 값을 날짜 칸으로 넘기지 않고, 연속 주 스크롤 보기만 요약 표시. 기록 템플릿 요약은 두 방식 모두 표시.

**G4 · `recTpl` — 기록 템플릿** (spec §15)
기간을 정해 쌓는 기록. 기본 제공: **공부**(시간·과목 태그·메모), **독서**(쪽수·책 제목 태그·메모), **운동**(분·메모).
- 커스텀: 이름 · 주 지표 이름 · 단위 · 태그 사용 여부와 이름 · 메모 사용 여부. 기본 템플릿은 복제해서 수정.
- ⚠ 템플릿을 지워도 저장된 기간·값 기록은 남고 무시됨.

**G5 · `recApply` — 기간 적용** (spec §15)
템플릿을 시작일·종료일 **포함** 기간에 적용. 새 기간 기본값 = 오늘부터 6일 뒤.
- 선택 가능 범위: 약 2년 전 ~ 3년 뒤. 같은 템플릿이 같은 날짜에 겹치면 하나로 정리. 여러 템플릿·여러 기간 동시 적용 가능.

**G6 · `recEntry` — 기록 입력** (spec §15)
주 지표 + 태그 + 메모. 변경 시마다 즉시 저장.
- **주 지표는 0 ~ 100,000 제한.** 단위가 정확히 `h`일 때만 0.5 단위, 그 외 1 단위. 주 지표가 0이면 그 값을 지움. 태그는 정확히 같은 문자열 중복 불가. 메모를 공백만 남기면 메모를 지움.

### H. 공유 · 스포츠

**H1 · `shared` — 공유 캘린더** 🔒(계정 필요) (spec §10)
카테고리를 코드로 공유하고 다른 사람의 카테고리를 구독. **로그인 + Supabase 연결 모두 필요.**
- **소유자**: 카테고리와 그 카테고리의 **시간표 아닌** 일정이 함께 올라감(공유 형식 2). 일정 변경은 약 3초 묶음 처리, 일부 카테고리 변경은 즉시 반영. 예전 메타데이터만 있는 형식 1도 계속 읽을 수 있음.
- **구독자**: 구독한 카테고리·일정은 읽기 전용. 수동 새로 고침과 편집 가능한 내 카테고리로 복제 지원 — **복제는 일정을 가져오지 않음.** 구독 해지 시 로컬 구독·일정 캐시·실시간 채널 정리.
- ⚠ 한계: 소유한 로컬 카테고리를 지워도 서버의 공유 행은 지워지지 않음 / 실시간 삭제 이벤트는 처리하지 않음 / 변경 종류는 일정 개수 비교로만 판단(늘면 추가, 줄면 삭제, 같으면 수정).
- 미로그인 상태: 자물쇠 아이콘 + "계정이 필요한 기능입니다" 빈 상태 + 로그인 버튼.

**H2 · `shareCode` — 공유 코드** 🔒 (spec §10)
**8자리 코드.** 헷갈리는 `I·O·0·1` 제외.
- 링크: `surlap://theme/<코드>` 및 `https://kev208dev.github.io/Surlap/theme/<코드>`. 앱이 꺼져 있을 때와 켜져 있을 때 모두 처리, 코드는 **대문자로 정규화**. OS 공유 시트 사용, 실패하면 코드와 링크를 복사할 수 있게 표시.
- ⚠ 플랫폼: 안드로이드는 HTTPS 앱 링크 설정 완료 / iOS는 커스텀 스킴만 설정, 유니버설 링크 미완료.

**H3 · `subscribe` — 코드로 구독** (spec §10)
8자리 코드 직접 입력. 소문자 입력도 대문자로 변환 처리, 이미 구독 중이면 안내.
- 상태 4종: 형식 오류 / 중복 구독 / 찾을 수 없음 / 네트워크 오류.
- 구독 직후 현재 공유 내용을 한 번 받아옴. 이후 변경은 실시간으로 받아 즉시 알림.

**H4 · `sports` — 스포츠 구독** (spec §11)
EPL · NBA · 포뮬러 1 · 리그 오브 레전드 일정을 읽기 전용 캘린더 항목으로. 구독 ID 형식 = `종목:리그:팀`.
- **가져오기**: 구독 즉시 **3일 전 ~ 60일 뒤** 받아와 로컬 저장. 앱 시작 시 켜진 구독 전체 새로 고침. UTC를 기기 날짜·시각으로 변환. 알림은 **꺼짐 → 10분 → 30분 → 60분 전** 순환.
- **실패 처리**: 새로 고침 실패 시 저장된 일정 유지 / 전체 새로 고침 성공했는데 결과가 비어도 기존 저장분 유지 / **한 구독만 새로 고쳤을 때 결과가 비면 그 구독의 저장분은 비워짐** / API 설정이 없어도 앱이 멈추지 않음.
- ⚠ 한계: 구독에 켜고 끄는 내부 상태가 있지만 관리 화면에 노출되지 않음 / 구독을 끄거나 지워도 이미 예약된 알림이 모두 취소되지는 않음 / 중계 주소 칸은 채워지지 않음.

**I1 · `profile` — 프로필 · 설정** (spec §4)
학교·기록·캘린더·앱 설정 진입점. 로그인 여부에 따라 계정 필요 항목을 구분 표시.

**I2 · `notif` — 알림** (spec §17)
**로컬 알림만.** 시간대 `Asia/Seoul`, 기기가 쉬는 중에도 보낼 수 있는 느슨한 예약. **모두 기본값 꺼짐.**
- **일정 알림**: 정시·5·15·30·60분 전. 앞으로 올 **내 시간 일정만**, 시간표 제외. 반복 생성분·공유·스포츠·학사·생일 제외. **최대 60건 예약.**
- **브리핑**: 6·7·8·9·10·12·18·21시 중 선택해 매일 반복. 오늘 내 일정 수와 남은 할 일 수를 **예약 시점에** 문구로 만듦.
- **생일**: 09:00 알림, 당일·1·3·7·30일 전 중 선택, 매년 반복.
- ⚠ 한계(고지 필요): 생일 알림을 다시 예약할 때 **전체 취소를 호출해서 예약해 둔 일정·브리핑·스포츠 알림까지 함께 사라질 수 있음** / 스포츠 구독을 만들 때 알림 권한을 따로 요청하지 않음.

**I3 · `bdays` — 생일** (spec §16)
직접 등록하는 매년 반복 생일. **이름·월·일 필수, 연도 선택.**
- 규칙: 없는 날짜는 그 달의 마지막 날로 맞춤 / **2월 29일은 평년에 2월 28일로 처리** / 오늘이면 남은 날 0 / 날짜 선택은 1900년 ~ 올해 기준 10년 뒤.
- ⚠ 연락처나 VCF 가져오기 흐름은 없음 — 여러 건을 한 번에 넣는 내부 로직만 존재.
- D-day는 `accent-2` 13px/700.

**I4 · `backup` — 백업 · 복원 · 내보내기** (spec §19)
iCalendar 내보내기 / 로컬 JSON 백업·복원 / 클라우드 업로드·다운로드.
- **iCalendar**: 제목·시작·종료·UID·매주/매월/매년 반복 규칙 포함. **시간표·학사·생일·스포츠 일정 제외.** 종일 일정은 다음 날을 종료로 적어 하루를 표현.
- **복원**: `.json` 파일만, `_v`가 **2**여야 함. 파일에 있는 항목만 적용하고 없는 항목은 지우지 않음. 일정과 카테고리만 즉시 반영되고 나머지는 앱 재시작 후 반영될 수 있음.
- ⚠ JSON 내보내기는 문서 폴더에 저장하고 경로만 알려줌 — 자동 공유 안 함.

**I5 · `account` — 계정** 🔒 (spec §2 · §3)
게스트 데이터는 `guest::`, 로그인 데이터는 `user_<uid>::` 접두사로 **물리적으로 분리.** 계정을 바꾸면 활성 범위가 바뀌고 관련 상태가 새로 만들어짐.
- 규칙: 가입·로그인해도 게스트 데이터는 자동 병합되지 않음 / 언어·온보딩 완료·캘린더 이동 설정·알림 설정은 계정 범위 밖 / 호환되는 첫 업그레이드에서 예전 데이터를 게스트 범위로 옮기고, 옮기기 전 전체 스냅샷 저장.
- ⚠ **클라우드 일정 형식 손실**: 동기화되는 일정 행에는 날짜·제목·시간표 여부·첫 카테고리·순서·사용자 ID만 들어감. **왕복하면 시작·종료 시각, 일정 ID, 반복, 두 번째 이후 카테고리가 사라짐.** 마지막 일정이 지워져 날짜 자체가 사라지면 서버에 남은 행이 정리되지 않을 수 있음.

**I6 · `delAccount` — 계정 삭제** 🔒 (spec §2)
확인을 거쳐 계정과 관련 데이터 삭제. **되돌릴 수 없음.**
- **지우는 것**: 내가 만든 일정 행 / 동기화된 사용자 데이터 행 / 테마 구독·기여·백업·소유한 공유 캘린더 기록 / Supabase 인증 사용자와 저장된 자동 로그인 정보.
- **로그인 없이 요청**: 형식이 올바른 이메일 주소를 받아 삭제 대기열에 넣음. 데이터베이스 오류는 노출하지 않고 접수 완료로 안내. 처리에 **최대 30일**. 상태는 대기·처리됨·실패.
- 파괴적 확인: `accent-2-100` 배경 + `accent-2-800` 텍스트 경고 배너("되돌릴 수 없습니다") → 최종 다이얼로그("정말 삭제할까요?").
